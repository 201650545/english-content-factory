## 三、版面工程（本项目最核心的可复用方法）

### 3.1 「每面 20 词 + 上下顶格」是怎么做出来的

- 词条**不拆列**：词头一行（词 + 音标 + 词性·释义）→ 搭配（CSS Grid 双列）→ 红笔批注
- 词条流用 `column-count:2`，单页容量翻倍
- **实测锚点：动词/搭配条目 20 词/页，填充率 96%**（字号：词 12.2pt / 含义 9.1pt / 搭配 9.2pt / 批注 8.8pt）

### 3.2 填充率计算式（判断"排版有没有浪费"）

```
填充率 = (内容最底部文字的 y 坐标 − 内容区顶部 y) / 内容区高度
```

## ★★ 硬性要求（郭老师 2026-10-15 定，不可协商）

> ### **每一页的填充率必须 ≥ 90%**
>
> 达不到的三种处理方式，**按优先级**：
> 1. **补内容**（首选）—— 加真信息（多一组辨析、多一个节点、多一道练习）
> 2. 放大字号 / 行距 —— 但不能低于字号底线（正文 10pt）
> 3. 换版式 —— 换更适配该内容量的形式
>
> **绝对禁止**：为填满页面而增加没有实际价值的文字（GPT 原话："你做的是备考资料，不是排版展示册"）。

**统一网格与检测口径**

| 项 | 值 |
| :--- | :--- |
| 内容区 | **182mm 宽 × 230mm 高** = 297 − 28(上下边距 14×2) − 21(标题) − 8(页脚) − 10(安全区) |
| 内容区 y 范围 | 35mm – 265mm |
| 填充率下限 | **90%**（硬性） |
| 检测工具 | `D:\小浣熊\_check_layout.py`（见下） |

**⚠️ 检测必须排除页脚区** —— 本项目踩过：把页脚文字算进内容区，五张样张全报 105%。越界判定用的是"内容区下界 + 2pt"，页脚区（内容区下界 +12pt 以外）单独统计、不计入填充率。

**A4 容量公式（GPT 提供，用于事前估算）**

```
行高：10pt ≈ 4.6mm
H单条 = L × 4.6 + P          （L = 行数，P = 上下内边距 mm）
N     = ⌊ (230 + G) / (H单条 + G) ⌋   （G = 条目间距 mm）
注意：双列容量不能简单乘二 —— 变窄后英文例句可能从一行变两行，必须重算行数。
```

**空白容忍度**：< 15–25mm 不用管；**> 50mm 才说明内容与版式不匹配**。
（但既然已定 90% 硬线，这条只作为"为什么空"的归因参考）

| 脚本 | 作用 |
| :--- | :--- |
| `D:\小浣熊\_check_layout.py` | **通用版面质检**：几何越界 + 填充率 ≥90% 硬门槛（排除页脚）。用法：`python _check_layout.py <pdf> [--top-mm 35 --bottom-mm 265 --min-fill 90]` |

### 3.4 内容不足时的取舍顺序（用户定）

1. **补内容**（首选，加真信息）
2. 放大字号/行距（次选）
3. 换版式（最后）

## 四、技术坑清单（每一个都真实踩过）

| # | 坑 | 现象 | 正确做法 |
| :--- | :--- | :--- | :--- |
| 1 | **CSS 花括号被批量替换吃掉** | 表格边框/行高全失效，填充率从 95% 掉到 45%，**不报错** | 用 `_css_check.py` 做花括号配平检测；**改样式要改一处验一处**，别做大范围字符串替换 |
| 2 | **`overflow:hidden` 裁切** | 超出内容静默消失 | 每页固定高度 `sheet` 必须配几何越界检测 |
| 3 | **PDF 文本层假通过** | 被裁掉的文字**仍在文本层**，`关键字能搜到` 不等于显示出来 | 完整性检测 **必须 + 几何越界检测**（只看文本层会骗过自己） |
| 4 | **`column-count` 溢出丢内容** | 内容超两栏时溢出到第 3 栏，整段**不进 PDF** | 控制每页条数，宁少勿多 |
| 5 | **`column-fill:auto` 版面不稳定** | 临界点上溢出量从 821pt 跳到 835pt | 用默认 `balance`，稳定优先 |
| 6 | **`nowrap + ellipsis` 藏内容** | 搭配显示成"与……交…" | 教辅**禁止省略号截断**，一律允许换行 |
| 7 | Chrome 渲染污染用户浏览器 | — | 渲染用**独立 `--user-data-dir` 临时 profile**，不碰用户窗口 |
| 8 | 文件名含全角字符 | `＿` 会 EPERM | 文件名只用 ASCII 下划线 |

### 两条铁律（郭老师 2026-10-15 定，都栽过）

1. **同一会话只能发一次**。连发两条会顶掉这一轮 → 表现为 `Validation failed` / 会话失效。
2. **回复显示 `Connection interrupted. Waiting for the complete answer` 时，一律直接刷新**。
   刷新会重新拉取服务端已生成的完整答案（实测 55 字占位 → 刷新后 7838 字全文）。
   **不要等、不要重发。**
   → 已固化进 `wait_and_fetch.py`：检测到中断占位自动 `location.reload()`，最多 3 次。

### 环境注意

- `opencli` 的 `eval` **跟随浏览器活跃标签**；`--tab` 在本版本不生效，用 `tab select <id>` 钉住目标
- 会话页（`/c/...`）里 `Chat | Work` 单选钮不存在，闸门脚本会返回 `chatState:null` → `ok:false`，
  但**只要 `modelOk:true` + `pill:High` 即可发问**
- 新手开标签用 `tab new`，**绝不碰用户已打开的标签**
- `send_turn.py` / `wait_and_fetch.py` 不带 `--tab`，会打到活跃标签 → 使用前先确认活跃标签是自己开的

## 十一、第二轮问诊结论（2026-10-15 · 9639 字）

全文：`镜像站回复2_音节着色与版面容量_20261015.md`

### 1. 音节着色：用「轻切分 + 强重音」，不要每音节一色

| 项 | 规定 |
| :--- | :--- |
| 切分符号 | **统一用中点 `·`**（`im·por·tant`）。斜杠 `/` 会和 IPA 冲突、连字符 `-` 会和正式拼写混 |
| 重音标记 | **加粗 + 下划线**（黑白打印照样看得出）；彩色只做增强，不做唯一识别手段 |
| 颜色上限 | **只加 1 层**（非重读=黑/深灰，重读=加粗+浅黄底）。再给每个音节上色会与现有三色系统打架 |
| 是否程序自动拆 | **不要**。发音音节 ≠ 拼写分段，不能按元音字母数机械切 |
| 适用范围 | **只挑 30–60 个**三音节以上/8 字母以上/易拼错的多音节词做切分；**单音节词不拆**（make/take/get/look 拆了没意义） |
| 版式 | 一页 2 列 × 3 行 = **6 个深度词条**；卡片 88×68mm；整词 12–13pt，IPA 9–9.5pt |

### 2. A4 容量网格与公式（以后所有样张统一用它）

```
可用内容区 = 182mm 宽 × 230mm 高
  297 − 28(上下边距) − 21(标题区) − 8(页脚) − 10(安全区) = 230mm

行高：10pt ≈ 4.6mm
H单条 = L × h + P        （L=行数，h=行高，P=上下内边距）
N     = ⌊ (230 + G) / (H单条 + G) ⌋   （G=条目间距）
```

**字号底线：正文不得低于 10pt**（9pt 不做正文）；词条主词 12–13pt；音标 9–9.5pt；红批 9.5–10pt；标题 15–17pt。

**空白判断**：< 15–25mm 不用管；**> 50mm 才说明内容与版式不匹配**。
**最忌讳**：为填满页面而增加没有实际价值的文字。

### 3. 各样张的目标配比
