# Education Content Factory (教育内容工厂)

> 当前版本：**v0.0.1**  
> 体系定位：基于教育语料与认知科学的数据驱动型内容生成系统

---

## 一、系统定位与边界划分

本系统旨在构建可追溯、可验证、工业级标准化的教育内容生产流水线。在整体架构中，Obsidian 与外部脚本/Agent 实行严格的**职责正交解耦**：

### 1. Obsidian 的职责（认知与治理控制台）
* **项目控制台**：统一总览所有子项目状态、推进节奏与关键指标。
* **Agent 协作协议**：固化人机协作、Agent 启动、交接与执行规则。
* **状态管理**：标准状态机驱动，记录各阶段生命周期变更。
* **方法记录**：沉淀教研规则、清洗判定标准与算法定义（Methodology）。
* **人工审核入口**：作为人类领域专家把关、仲裁 Issue 与签发 Release 的主界面。
* **格式约束**：Markdown 仅负责规范、项目状态和人类可阅读信息；严禁将大规模单词表、分词语料拆散成海量 Markdown 文件。

### 2. 外部脚本 / Agent 的职责（计算与生产执行引擎）
* **文件解析**：解析 PDF、Word、OCR 等非结构化输入。
* **数据清洗**：按规则去噪、提取题干/选项/听力正文。
* **数据统计**：执行词频统计、共现分析、难度加权计算。
* **内容生成**：调用 LLM / 提示词配方生成例句、考点解析、教学微课稿件。
* **文件渲染**：将排版模板与结构化数据渲染为最终出版物（Typst、LaTeX、HTML、PDF等）。
* **自动化执行**：CI/CD 批处理与工作流自动化调度。

## 二、目标端到端流程

系统完整业务生命周期定义如下：

```
原始教育资料 (SOURCE)
       ↓
数据结构化 (INGEST / CLEAN / NORMALIZE)
       ↓
数据分析 (ANALYZE / VERIFY)
       ↓
教育内容生成 (ENRICH / CONTENT)
       ↓
排版 (RENDER)
       ↓
质量验证 (QA / REVIEW)
       ↓
发布 (PUBLISH)
       ↓
到期免费 (FREE)
       ↓
归档 (ARCHIVE)
```

## 四、核心原则 (v0.0.1 约束)

1. **最小可运行骨架**：v0.0.1 仅建立工作流契约、数据规范与项目目录框架，不提前实现具体阶段。
2. **零侵入与真实性**：不抓取未经确认的真题，不虚构词频数据，不擅自做教研决策。
3. **不可变与可追溯**：原始输入资料一经放入 `01_raw/` 即为只读不变资产。
4. **遇疑必记**：遇到模糊或不确定规则，全量写入对应项目的 `ISSUES.md` 并标记 `needs_review`，严禁猜测。
5. **结构化数据归位**：结构化与大数据集统一归入 CSV / JSON / SQLite，保持 Obsidian 仓库纯净敏捷。
